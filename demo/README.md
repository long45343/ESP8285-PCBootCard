# 在线演示

这是固件里三个网页的纯前端模拟版本，不连接任何真实设备。

## 看什么

- **配网页面**：模拟第一次配置时的界面，可以扫描 WiFi、选择控制方式、设置网页密码
- **登录页面**：模拟设置密码后的登录界面，演示密码是 `demo123`
- **状态页面**：模拟日常维护界面，可以看日志、扫描 WiFi、改密码、切换连接方式、升级固件

右下角有一个「模拟设备」面板，点开可以手动触发开机、关机、重启，观察状态页面和日志怎么变化。

## 本地运行

不需要装任何东西，直接用浏览器打开 `index.html` 就行。

如果浏览器对本地文件有限制，可以起一个静态服务器：

```bash
python -m http.server 8000
```

然后访问 `http://localhost:8000/demo/`。

## 部署到 GitHub Pages

这个目录是纯静态文件，可以直接用 GitHub Pages 托管。

仓库现在的做法是把 Pages 的来源设成 `main` 分支的根目录：根目录的 `README.md` 会被渲染成首页，`demo` 子目录作为静态文件一起发布，所以演示地址是 `https://<用户名>.github.io/<仓库名>/demo/`。

有个容易踩的地方：Pages 的「分支部署」下拉框只提供根目录和 `/docs` 两个选项，选不到 `/demo`。但这只是说不能把 `/demo` 单独设成站点根，选根目录之后仓库里的子目录照样能访问，不需要把 demo 挪到别的位置。

如果想让演示直接占据站点根（打开 `https://<用户名>.github.io/<仓库名>/` 就是演示页面），可以改成 GitHub Actions 部署：仓库里已经带了 `.github/workflows/pages.yml`，把 Settings → Pages 的 Source 切成 **GitHub Actions** 即可。

## 说明

演示里的所有数据都是写死的假数据，包括：

- WiFi 名称和信号强度
- IP 地址 `192.168.31.100`
- 巴法云主题名 `pcpwswb2c3006`
- 运行时间和内存占用

这些值在 `app.js` 顶部的 `state` 对象里，想改直接改就行。
